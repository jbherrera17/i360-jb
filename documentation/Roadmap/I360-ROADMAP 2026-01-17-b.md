## What's New in v3.15

### Context Asset Version History Fix (Bug Fix)

| Component | Description |
|-----------|-------------|
| **Root Cause** | Database trigger on `context_assets` auto-creates version history entries on UPDATE |
| **Problem** | Duplicate key constraint violation caused entire transaction to rollback |
| **Solution** | Delete conflicting version entry before update to allow trigger to succeed |

### Issue Details

When updating context assets, a database trigger automatically inserts records into `context_asset_versions` for audit history. If a version record already existed (from prior saves or sync issues), the duplicate key constraint caused:
- Transaction rollback
- Asset update silently failing
- User seeing "success" but changes not persisting

### Solution

Before updating the asset, delete any existing version entry that would conflict with the trigger:

```javascript
// Delete conflicting version entry before update
const triggerVersion = current.version || 1;
await supabase
    .from('context_asset_versions')
    .delete()
    .eq('asset_id', id)
    .eq('version', triggerVersion);
```
