## Infrastructure Integration Fixes

The Support AI module (Phase 71) shipped with several disconnections from existing platform infrastructure. All have been resolved:

| Fix | Before | After |
|-----|--------|-------|
| Knowledge base processes search | Query used `.eq('org_id')` on a table with no `org_id` column — always returned empty | Uses department-based org-scoping (Parthenon pattern) |
| Support Settings Policies tab | Rendered from hardcoded JavaScript array | Fetches live data from Parthenon processes API |
| KB content search | Only searched `name` and `description` fields | Now also searches `content_text` for richer results |
| "Edit policies" link | Pointed to `/processes.html` (404) | Points to `/parthenon.html#processes` |
| API authentication | Missing `auth-fetch.js` — raw `fetch` calls would fail on token expiry | All calls use `authFetch()` with automatic token refresh |
| Admin discoverability | Support Settings not on admin dashboard | Added tile in Platform & Access section |

## Developer Standards

Added a **mandatory New Module Integration Checklist** to `CLAUDE.md` with 30+ checkboxes across 8 categories. Every new module must pass all checks before it can be declared complete:

1. Platform Module Registration (DB fields, role access, nav link)
2. Route Registration (factory pattern, middleware, route ordering)
3. Data Scoping (correct column scoping patterns)
4. Frontend Integration (authFetch, navigation, ModalService)
5. Infrastructure Connections (use existing APIs, no dead links)
6. Documentation Chain (user guide, help registry, docs whitelist)
7. Testing (unit + integration)
8. Verification (manual end-to-end check)
