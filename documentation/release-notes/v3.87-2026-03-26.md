## Security Fixes

### Cross-Tenant Data Leak (CRITICAL)

The `/api/prompts/history` endpoint returned transformed assets from **all organizations** with no tenant filter. Any authenticated user could see other organizations' transformed skills, agents, and context assets.

**Fix:** Added `.eq('org_id', orgId)` to all three queries (skills, agents, context_assets) in the history endpoint, plus a 403 guard if org context is missing.

### Missing Auth Middleware (CRITICAL)

The entire `/api/prompts/*` route had no module-level access control. While the global `authenticate` middleware prevented unauthenticated access, any authenticated user from any org could invoke all endpoints without module or tier gating.

**Fix:** Added `requireModule('higgins')` middleware to gate all prompts endpoints through the Higgins module (available to all tiers and roles).

### Missing Tenant Isolation on Inserts (CRITICAL)

All three insert operations (skills, agents, context_assets) created records without an `org_id` field, producing orphaned records not associated with any organization.

**Fix:** Added `org_id: getVerifiedOrgId(req)` to all insert operations, with a 403 guard if org context is missing.

### Information Leak in Error Response

The transformation error handler included `raw_response` (first 500 characters of AI output) in the HTTP response body, potentially leaking transformation details.

**Fix:** Moved `raw_response` to server-side `console.error` only — no longer sent to the client.

## Bug Fixes

### "Save to Insight 360" — 100% Broken (P0)

The TransformAssetModal's save feature failed for every user with "Network error while saving." Root cause chain:
1. Frontend used raw `fetch()` instead of `authFetch()`, missing the `x-org-id` header
2. Backend had no auth middleware, so `req.userId` was never populated
3. Save path returned 401 ("Authentication required") because userId was always null
4. Error caught in frontend catch block, displayed as generic "Network error"

**Fix:** Complete rewrite of the save flow (see New Features below).

### User Edits Silently Discarded

When users edited fields in the Step 2 preview form (name, description, system prompt, etc.) and clicked "Save to Insight 360", the save handler re-sent the original prompt for re-transformation, discarding all user edits.

**Fix:** New `/api/prompts/save` endpoint accepts the edited form data directly — no LLM call on save.

### Visibility Default Fails Open

When the user permissions lookup failed, visibility defaulted to `'team'` (broader access) instead of `'private'` (narrower access).

**Fix:** Default changed to `'private'` — fail-safe.

### Broken `/preview` Endpoint

The `POST /api/prompts/preview` endpoint used `router.handle(req, res)` which is not a valid Express method, causing a runtime error.

**Fix:** Removed the broken endpoint. Preview is handled by calling `/transform` with `save=false` from the frontend.

### Stale Model Reference

The transformation and agent creation used a hardcoded model ID (`claude-sonnet-4-5-20250929`) that would break on model rotation.

**Fix:** Replaced with `getDefaultModel('anthropic')` from `llmRegistry.js`, with fallback.

## New Features

### `POST /api/prompts/save` Endpoint

New dedicated endpoint for saving user-edited transformed data directly to the database without triggering an LLM call.

| Field | Description |
|-------|-------------|
| `target_type` | `skill`, `agent`, `voice_dna`, `icp`, or `business_profile` |
| `data` | User-edited form fields matching the target schema |
| `source_prompt` | Original prompt text (for provenance tagging) |

Benefits:
- User edits are preserved exactly as entered
- No wasted LLM API calls on save (faster, cheaper)
- Clean separation between transformation (AI) and persistence (save)
- Full validation, org_id injection, and duplicate name handling
