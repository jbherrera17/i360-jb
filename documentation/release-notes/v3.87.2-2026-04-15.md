## What Changed

### `.gitignore` — extension rule was too broad

The old rule `extension/` matched any directory named `extension/` anywhere in the tree, including `__tests__/integration/extension/`. Four test files lived there for a while but were never committed. Fix:

```
-extension/
+# Chrome extension build folder (root only)
+/extension/
+!__tests__/integration/extension/
```

Now the rule only matches a root-level `/extension/` directory.

### `mockSupabase.js` — `createOwnershipQueryBuilder` + ownership allowlist

Phase 82 routes typically have per-resource ownership checks (`verifyAgentOrgOwnership`, etc.) that query the resource table by id with `.maybeSingle()`. The prior default query builder returned `null`, so every ownership check returned 404 unless the test explicitly mocked the table.

New helper `createOwnershipQueryBuilder()` returns a builder whose:

- `.single()` / `.maybeSingle()` resolve to `{data: DEFAULT_TEST_RESOURCE_OWNERSHIP, error: null}` — a synthetic "I exist and belong to test-org-001" record
- Thenable (plain `await` on a chain) resolves to `{data: [], error: null, count: 0}` — empty array for list queries

A new `OWNERSHIP_DEFAULT_TABLES` set lists tables that get this builder automatically:

```javascript
agents, workflows, departments, processes, okrs,
actions, skills, clients, conversations
```

Tests that need "not found" (404) or "wrong org" (403) behavior must still opt in by explicitly mocking the table to return `null`.

### Per-suite test fixes

**`parthenon.test.js`** (31 → 3 failures)
- Added `maybeSingle`, `limit`, `range` to the local `createChainable` helper so the mock matches what the production handlers chain.
- Converted 26 unscoped `mockSupabase.from.mockImplementation(() => X)` calls to table-aware `(t) => t === "organization_members" ? ... : X` form so the auth membership check isn't clobbered.
- Replaced a narrow `{update, delete, eq}` mock in the DELETE /departments/:id test with `createChainable({id, org_id})` so the ownership chain resolves.

**`actions.test.js`** (21 → 4 failures)
- Same three changes as parthenon.
- Plus changed `return createQueryBuilder()` fallbacks to `return createMockSupabase().from(table)` so unhandled tables inherit the membership default.

**`agents.test.js`** (17 → 7 failures)
- One-line fixture fix: `testAgents.contentWriter` (undefined) → `testAgents.systemAgent`. The former didn't exist in the fixtures file, so the test was passing `[undefined]`, which crashed `resourceAccess.js` on `undefined.is_system`.

**`chat.test.js`** (18 → 6 failures)
- Added two missing mock methods on `llmRegistry`:
  - `resolveModelId: jest.fn(value => ({valid, model}))` — `validate.js` calls this during zod parsing
  - `getModelDisplayInfo: jest.fn(model => ({id, name, provider}))` — `higginsService` calls this during chat processing

**`extension/agent-stream.test.js`** (11 → 1 failure)
- Changed the default fallback in `from.mockImplementation` from a narrow builder to `createMockSupabase().from(table)` so `organization_members` gets the membership default.

**`extension/conversations-bearer.test.js`** (24 → 0 failures)
- Added `jest.mock('@supabase/supabase-js', ...)` at the top of the file to stub the module-level `createClient` in `conversations.js`. That file isn't a factory — it calls `createClient(SUPABASE_URL, SUPABASE_KEY)` at require-time and passes that client to `requireOrgContext`. The test's `mockSupabase` can't intercept that. Mocking the SDK itself is the only clean workaround without refactoring `conversations.js`.

### `clients.test.js` — 5 → 2 failures (no direct change)

Benefit from the shared `createOwnershipQueryBuilder`. The ownership-check tests that previously fell through to a null default now get a valid record by default.
