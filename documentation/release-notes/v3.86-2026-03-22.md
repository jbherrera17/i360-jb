## Agent Library UI/UX Overhaul

The Agent Library page (`agents.html`) has been completely redesigned for improved usability and information density.

### Layout Changes

| Before | After |
|--------|-------|
| 3-panel layout (list + empty center + narrow sidebar) | 2-panel master-detail (list + unified detail panel) |
| 2150 lines of inline CSS | Extracted to `/css/agents.css` |
| 5 filter dropdowns always visible | Search as hero + 2 primary filters + collapsible advanced |
| Full-width action buttons on every card | Hover-to-reveal icon buttons |
| No agent descriptions in list | 1-line description snippet per card |
| No keyboard support | Full keyboard navigation |

### Tabbed Edit Modal

The agent edit modal now has three tabs:

| Tab | Content |
|-----|---------|
| **Settings** | Agent form (name, icon, system, category, description, platform config, system prompt, model, temperature, conversation starters) |
| **Context** | Current mappings list with remove buttons + inline add form (type filter, asset select, mode, priority) |
| **History** | Recent execution history (date, status, preview, tokens, duration) |

This eliminates the UX disconnect where editing an agent required closing the modal to manage context mappings in a separate panel.

### Detail Panel

The right panel shows a complete read-only view of the selected agent:
- Header with icon, name, badges, and action buttons (Run, Edit, Duplicate, Archive)
- Overview stats (total runs, status)
- Configuration metadata (platform, model, system, category, department, created/modified dates)
- Context mappings with injection modes
- Recent execution history

### Additional Improvements

- **Compact/Detailed view toggle** — switch between card views
- **Keyboard navigation** — Arrow keys, Enter, Escape, `/` (search), `N` (new), `E` (edit)
- **Keyboard hints bar** — visible at bottom of agent list
- **ModalService.confirm** for delete (was browser `confirm()`)
- **ModalService.form** for duplicate (was `window.prompt()`)
- **Lucide icons** in empty states (was emoji)
- **CSS variables** throughout (no hardcoded hex colors)

## Context Route Tenant Isolation

`server/routes/context.js` has been hardened for multi-tenant data isolation:

| Change | Detail |
|--------|--------|
| Factory pattern | Converted from bare router to `module.exports = function(supabase)` |
| Org scoping | `scopeToOrg(query, orgId)` replaces unsafe `.or(org_id.eq.${orgId},org_id.is.null)` |
| Platform admin scoping | Admins are now scoped to their org on normal endpoints (cross-org only on admin endpoints) |
| Ownership validation | `GET /assets/:id` validates `org_id` matches requester's org |
| Header resolution | Lightweight middleware sets `req.verifiedOrgId` from `x-org-id` header |

**Security impact:** Platform admin accounts can no longer see context assets from all organizations on the standard `/api/context/assets` endpoint. Cross-org access is restricted to explicit admin endpoints (`/api/platform/*`).

## XSS Hardening

Added `escapeHtml()` to all unescaped data in context mapping rendering:
- `asset.name`, `asset.icon`, `asset.asset_type`, `mapping.injection_mode` — 4 rendering paths fixed
- `categoryLabel` in agent card badges — 1 additional fix
- Pre-existing vulnerability (not introduced by this release), now resolved

## Critical Production Fix

**Issue:** `chat.js` called `loadModels()` before `authFetch` was available, causing models not to load on production.

**Root cause:** `DOMContentLoaded` handler in `chat.js` called API functions without waiting for `initNavigation()` to load the `authFetch` module.

**Fix:** Added `await initNavigation()` before `loadModels()` in `chat.js` DOMContentLoaded handler.
