## New: Artifact System

The Artifact System provides a persistence layer for deliverables produced across the platform. Previously, agent outputs and skill results existed only as ephemeral chat text. Now they are saved as browsable, downloadable artifact bundles.

### Key Capabilities

| Capability | Description |
|-----------|-------------|
| **Compound Bundles** | A single artifact can contain multiple parts: markdown reports, images, PDFs, spreadsheets, code snippets |
| **Source Tracking** | Every artifact tracks its origin: agent execution, workflow run, skill output, chat, manual upload, or API |
| **Versioning** | Create new versions of artifacts while preserving history |
| **Visibility Controls** | Private (owner only), Team (department), or Organization-wide |
| **Search & Filter** | Full-text search by name/description, filter by source type, tags, department |
| **Signed Downloads** | Binary files stored in Supabase Storage with time-limited signed URLs |

### Database Schema

| Table | Purpose |
|-------|---------|
| `artifact_bundles` | Parent container with source tracking, classification, versioning, generation metadata |
| `artifact_parts` | Child content pieces with dual storage (inline text + Supabase Storage for binary) |

### API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/artifacts` | List bundles (paginated, filterable) |
| GET | `/api/artifacts/my-recent` | User's recent artifacts |
| GET | `/api/artifacts/:id` | Bundle with all parts |
| POST | `/api/artifacts` | Create bundle with inline parts |
| PATCH | `/api/artifacts/:id` | Update metadata |
| DELETE | `/api/artifacts/:id` | Delete bundle + parts + storage |
| POST | `/api/artifacts/:id/parts` | Add text part |
| POST | `/api/artifacts/:id/parts/upload` | Upload binary file (50MB limit) |
| GET | `/api/artifacts/:id/parts/:partId/download` | Signed download URL |
| POST | `/api/artifacts/:id/version` | Create new version |

### Frontend

- **artifacts.html** — Full browse page with search bar, filter chips, card grid, detail modal with part preview/download, pagination, upload modal
- **Execute 120** — "My Artifacts" card showing 5 most recent artifacts with source type icons and quick view links

### Security

- Row Level Security: owner full access, org-visible readable by org members, team-visible by department
- `requireOrgContext` + `requireModule('artifacts')` on all routes
- Ownership validation on all mutations (PATCH, DELETE, parts)
- Service role bypass for server-side operations

## Deprecated: Strategy 120

Strategy 120 was an early-phase (Phase 8) strategic planning module that has been fully superseded by:

- **Execute 120** — the personal command center where users interact with agents by role
- **Claude Code skills** — Jarvis (decisions), Alfred (scenario planning), Ellis (OKR cascade), and 40+ department skills

### What Changed

| Change | Detail |
|--------|--------|
| Navigation link removed | No longer appears in sidebar |
| Page redirects | `/strategy120.html` now redirects (301) to `/execute120.html` |
| Module deactivated | `platform_modules.is_active = false` for `strategy_agents` |
| Execute 120 cleanup | Strategy overview card and related CSS removed |
| Route preserved | `server/routes/strategy120.js` kept (no user data, avoids migration issues) |
| Help entry removed | `/strategy120` removed from help registry |

Bookmarks to `/strategy120.html` will automatically redirect to Execute 120.
