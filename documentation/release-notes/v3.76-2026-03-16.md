## Bug Fixes

### Critical: Guardrail False Positives (affects ALL agents)

The bright line keyword matching algorithm in `guardrailEnforcementService.js` extracted high-frequency English words (human, safety, first, provide, information, data) as screening keywords. Any substantive message about AI/technology matched 5-8 keywords against a threshold of 3, causing false blocks.

**Fix:**
- Added 50+ high-frequency content words to the stop word filter
- Added length-normalized match threshold: longer messages require proportionally more matches
- Result: benign 200-word article went from 8/3 matches (BLOCKED) to 1/2 (OK), while real violations ("physically harm someone") still trigger 2/2 (BLOCKED)

### Critical: Guardrail Incident Logging Broken

The `bright_line_incidents` table had a CHECK constraint from Phase 54 that only accepted `violation`, `near_miss`, `inquiry`. Phase 59's guardrail service passes `bright_line` and `prompt_injection` types, causing silent insert failures.

**Fix:** Updated CHECK constraint to accept all 7 incident types. Upgraded silent `console.warn` to `console.error` with diagnostic hints.

### Medium: Header Image Generation Failure

GPT Image model returns base64 data as `imageData.base64`, but `tlImageService.js` looked for `imageData.b64_json`. Property name mismatch caused all GPT Image responses to fail with "no URL or base64 data."

**Fix:** Check both `b64_json` and `base64` properties.
