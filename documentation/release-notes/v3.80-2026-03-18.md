# Insight 360 v3.80 Release Notes

**Release Date:** March 18, 2026
**Phase:** 80 — LLM Health Monitoring & Automatic Fallback
**Previous:** v3.79 (Platform Admin Org Scope + Org Chart Updates)

---

## Highlights

- Real-time LLM provider health monitoring with 5-minute interval checks across all 4 providers
- Automatic transparent fallback when a provider goes down — users see a toast, not an error
- Circuit breaker bridge provides instant detection from real traffic (no 5-minute delay)
- SSE health stream pushes provider status changes to all connected frontends in real time
- Model dropdowns gray out unavailable providers with "(unavailable)" suffix
- Perplexity has no fallback by design (unique search capability) — returns clear 503

## What Changed

### Real-Time Health Monitoring

The `modelAvailabilityService` now maintains an **in-memory status cache** updated by two sources:

| Source | Latency | Mechanism |
|--------|---------|-----------|
| 5-minute interval | ~5 min worst case | 1-token ping to cheapest model per provider |
| Circuit breaker bridge | Instant | State change callbacks from real user traffic |

A Node.js `EventEmitter` (`healthEventEmitter`) broadcasts `status-change` events whenever a provider transitions between available/unavailable.

### SSE Health Stream

New endpoint `GET /api/health/stream` (authenticated) pushes provider status to the frontend:

| Event | Payload |
|-------|---------|
| `init` | Full provider status cache on connection |
| `status-change` | `{ provider, oldStatus, newStatus, error, updatedAt }` |
| `:heartbeat` | Keep-alive every 30 seconds |

### Chat & Agent Integration

Fallback resolution applied at **5 dispatch points**:

| Location | Type | Fallback Handling |
|----------|------|-------------------|
| `POST /api/chat/` | Non-streaming | `fallback` object in JSON response |
| `POST /api/chat/message` | Non-streaming | `fallback` object in JSON response |
| `POST /api/chat/stream` | Streaming (SSE) | `type: 'fallback'` event before content |
| `agentService.executeAgent()` | Non-streaming | `fallback` in result object |
| `agentService.streamAgent()` | Streaming | `fallback` in result object |

### Frontend Health Module

New `public/js/llm-health.js` provides `window.LLMHealth`:

| API | Description |
|-----|-------------|
| `isProviderAvailable(provider)` | Returns boolean |
| `getProviderStatus(provider)` | Returns `{ status, responseTime, error, updatedAt }` |
| `getAllStatuses()` | Full cache |

Automatically shows toast notifications on provider DOWN/UP transitions.

### Model Dropdown Graying

All model selectors listen for `llm-health-change` custom event:
- Unavailable provider options get `disabled = true` and `opacity: 0.5`
- Text appended with "(unavailable)"
- Restores automatically when provider recovers

## Circuit Breaker Bridge

Provider services (`anthropic.js`, `openai.js`, `gemini.js`) now register `onStateChange` callbacks on their circuit breakers:

- `CLOSED -> OPEN` or `HALF_OPEN -> OPEN`: marks provider as `unavailable`
- `HALF_OPEN -> CLOSED`: marks provider as `available`

This gives **instant detection** from real user traffic — a provider outage is detected the moment the circuit breaker trips, not at the next 5-minute poll.
