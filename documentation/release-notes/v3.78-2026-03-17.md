## Commit 3: Chat & Conversation Enhancements

**Hash:** `d21b20e`

### Fix: Save as Context Asset (Was Completely Broken)

The "Save as Context Asset" button in Higgins chat was non-functional:

| Before | After |
|--------|-------|
| Posted to `/api/context` (non-existent) | Posts to `/api/context/assets` (correct) |
| Used `type: 'knowledge'` (invalid) | Uses `asset_type: 'i360_knowledge'` (valid) |
| Sent `content` field (not in schema) | Sends `content_json: { content: ... }` |
| Manual token via `localStorage.getItem('auth_token')` | Uses `authFetch()` with proper token key |

## Commit 4: Context Asset Staleness Fix

**Hash:** `100be16`

### Problem

Every dropdown/selector showing context assets across the application cached data at page load and never refreshed. Users had to reload the page to see newly created assets.

### Root Cause

Frontend pages called `fetchContextAssets()` once during `init()` and stored results in a module-level array. Modal open handlers used the stale cache instead of re-fetching.

### Fixes Applied

| Page | Fix |
|------|-----|
| `agents.html` | Re-fetches on every context modal open + switched to `authFetch()` |
| `agent-runner.html` | Switched to `authFetch()` (already re-fetched on modal open) |
| `thought-leadership.html` | Clears `<select>` options before repopulating (prevented duplicate entries) + switched to `authFetch()` |
| `digest-sources.html` | Re-fetches on source add/edit + switched to `authFetch()` |
| `digest.html` | Re-fetches on section add + switched to `authFetch()` |

### Backend Fixes

| File | Fix |
|------|-----|
| `server/routes/context.js` | Added org ownership check on `GET /assets/:id` — blocks cross-org access while allowing platform/shared assets (`org_id = null`) |
| `server/routes/digest.js` | Fixed column name: `type` → `asset_type` (was querying wrong column) |
| `server/services/digestPipeline.js` | Fixed column names: `type, content` → `asset_type, content_text` (digest context blocks were silently empty) |
