## Commit 3 — Router scope leak fix (`9744247`)

**Production fix.** Eleven route files declared `const router = express.Router()` at module scope BEFORE the factory export. The factory then attached middleware and routes to that shared module-level router, so every subsequent call to the factory re-used the same router and compounded state:

- `router.use(middleware(supabase))` stacked more middleware each call
- `router.get/post/put/delete` double-registered handlers
- Middleware and handler closures kept a reference to the **first** `supabase` passed into the factory, forever

In production this is latent — `server/index.js` calls each factory exactly once at boot, so the bug doesn't manifest at runtime. But:

1. Hot-reload dev setups, any future multi-mount scenario, or a background worker that re-instantiates the router would compound state.
2. The Jest test harness was silently broken: tests create a fresh `mockSupabase` per test via `beforeEach`, but the router kept a closure over the **first** `mockSupabase`. Tests would call `mockSupabase.rpc.mockResolvedValue(...)` on the current mock and then see "Number of calls: 0" because the handler was calling a stale, earlier `mockSupabase.rpc` that the test didn't touch.

**Fix:** move `const router = express.Router()` inside the factory body in all eleven files. Matches the pattern already used by `chat.js`, `workflows.js`, `business-roles.js`, `departments.js`, `governance.js`, `integrity.js`, `users.js`, and `department-strategy.js`.

**Files changed:**

- `server/routes/modules.js`
- `server/routes/clients.js`
- `server/routes/connections.js`
- `server/routes/mcp.js`
- `server/routes/org-members.js`
- `server/routes/organizations.js`
- `server/routes/platformAdmin.js`
- `server/routes/platformMcp.js`
- `server/routes/pricing.js`

- `server/routes/roleAudit.js`

**No behavior change in production runtime** — `server/index.js` still calls each factory exactly once. Same router object, same routes, same middleware chain. The fix only affects repeat-call scenarios (hot-reload, tests, future multi-mount). **Impact:** 229 → 187 integration failures (+42 passing).
