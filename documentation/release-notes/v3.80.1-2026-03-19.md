# Insight 360 v3.80.1 Release Notes

**Release Date:** March 19, 2026
**Phase:** 80 (Patch) — LLM Health Check Billing Error Fix
**Previous:** v3.80 (LLM Health Monitoring & Automatic Fallback)

---

## Highlights

- Billing and quota errors are now correctly classified as "Billing Issue" instead of "Offline" or "Auth Error"
- Providers with billing issues are no longer treated as down — fallback is not triggered for account-level issues
- Dashboard, System Health, and Chat pages all display accurate provider status

---

## Problem

The Phase 80 health monitoring system misclassified billing/quota errors from API providers:

| Provider | Error | Old Status | Displayed As |
|----------|-------|------------|--------------|
| Anthropic | "Credit balance too low" (HTTP 400) | `unavailable` | "Offline" / "Unavailable" |
| Perplexity | "Exceeded current quota" (HTTP 401) | `auth_error` | "Auth Error" |

This caused:
- System Health page showing Anthropic as "Offline" when the API was functional
- Dashboard showing "Unavailable" with error styling
- Fallback triggering unnecessarily (switching to OpenAI/Google when Anthropic billing was low)
- Chat model selector graying out all Anthropic models

---

## Fix

### New `billing_error` Status

Added a sixth status classification that detects billing/quota errors by message content before falling through to HTTP status code checks:

| Provider | Detection Keywords |
|----------|-------------------|
| Anthropic | `credit balance`, `billing`, `purchase credits`, `exceeded` + `quota` |
| OpenAI | `billing`, `exceeded` + `quota`, `insufficient_quota`, `payment` |
| Google | `billing`, `exceeded` + `quota`, `payment` |
| Perplexity | `exceeded` + `quota`, `billing`, `payment`, `plan and billing` |

### Billing = Warning, Not Outage

`billing_error` is treated differently from `unavailable`:

| Behavior | `unavailable` | `billing_error` |
|----------|---------------|-----------------|
| Triggers fallback? | Yes | **No** (account-level, fallback won't help) |
| Dashboard display | "Unavailable" (red) | "Billing Issue" (yellow) |
| System Health display | "Offline" (red) | "Billing Issue" (yellow) |
| Chat models grayed? | Yes | **No** |
| Overall status | Error | Warning |
| Toast message | "...unavailable. Using fallback." | "...billing issue. Check your API plan." |

### REST API Cache Overlay

The `/api/models/availability` endpoint now overlays the in-memory cache on top of database results, ensuring the REST API reflects the current `billing_error` status even before the DB migration is applied.

## Database Migration Required

Run in Supabase SQL Editor:

```sql
ALTER TABLE model_availability_checks DROP CONSTRAINT IF EXISTS model_availability_checks_status_check;
ALTER TABLE model_availability_checks ADD CONSTRAINT model_availability_checks_status_check
    CHECK (status IN ('available', 'deprecated', 'unavailable', 'auth_error', 'rate_limited', 'billing_error'));
```

Without this migration, health check results will not persist to the database (gracefully handled — in-memory cache and SSE still work).
