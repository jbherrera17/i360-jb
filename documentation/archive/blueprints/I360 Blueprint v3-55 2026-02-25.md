## Phase 59e: Admin Tier Visibility, Org-Scoped Departments & Context Templates (v3.55)

### What Was Completed

Three distinct improvements were delivered in this phase:

1. **Admin page tier-based visibility** — Agency-specific UI elements (Client Portal stat card, Platform/Agency Teams/Client Portal filter buttons, Client/Portal table columns) are now dynamically hidden for non-agency organizations. The system detects the user's org subscription tier and applies `data-agency-only` attribute toggling.

2. **Org-scoped department filtering** — The departments API was returning all departments regardless of organization, causing duplicate entries in department lists. The GET endpoint now filters by `org_id` from query param, `x-org-id` header, or auth middleware. The POST endpoint now requires `org_id` to prevent orphan department creation.

3. **Context asset template support** — Context assets can now be flagged as templates with `is_template`. Template assets display a gold left border, "Template" badge, and a callout bar with a "Duplicate to Customize" button in the editor view.

### 1. Admin Page Tier-Based Visibility

The admin.html page now detects the current user's organization tier and conditionally shows/hides agency-specific UI elements:

| UI Element | Non-Agency Orgs | Agency Orgs | Platform Admin |
|-----------|----------------|-------------|----------------|
| Stats: "Platform Admins" | Shows as "Admins" | Shows | Shows |
| Stats: "Agency Members" | Shows as "Members" | Shows | Shows |
| Stats: "Client Portal" | **Hidden** | Shows | Shows |
| Filter: "Platform" | **Hidden** | Shows | Shows |
| Filter: "Agency Teams" | **Hidden** | Shows | Shows |
| Filter: "Client Portal" | **Hidden** | Shows | Shows |
| Table: "Client" column | **Hidden** | Shows | Shows |
| Table: "Portal" column | **Hidden** | Shows | Shows |

**Implementation:**
- `detectOrgTier()` checks `currentUser.is_platform_admin` and `organizations[].subscription_tier.startsWith('agency')`
- `applyTierVisibility()` toggles `data-agency-only` elements and relabels stat cards
- `updateAssignmentStats()` uses org membership roles (admin/member/viewer) instead of platform/agency/client counts for non-agency orgs
- `renderUsersTable()` conditionally includes Client/Portal columns

### 2. Org-Scoped Department Filtering

| Endpoint | Before (Broken) | After (Fixed) |
|----------|-----------------|---------------|
| `GET /api/departments` | Returned all departments, no org filter | Filters by `org_id` param/header/middleware; excludes null `org_id` orphans |
| `POST /api/departments` | No `org_id` field — created orphan records | Requires `org_id` (from body, header, or middleware); returns 400 if missing |

**Cleanup migration** (`phase59c-cleanup-orphan-departments.sql`):
- Deleted 18 orphan departments with `org_id IS NULL` (confirmed zero FK references in `department_agents`, `business_role_defaults`, `okrs`, `processes`)
- Added `NOT NULL` constraint on `departments.org_id`

### 3. Context Asset Template Support

| Feature | Description |
|---------|-------------|
| `is_template` column | Boolean flag on `context_assets` table (default `false`) |
| Template badge | Gold "Template" pill badge in asset list items |
| Left border highlight | 3px gold left border on template asset cards |
| Template callout | Info bar in editor: "This is a platform template. Duplicate it to create your own customized version." with "Duplicate to Customize" button |
| API support | `POST /api/context/assets` and `PUT /api/context/assets/:id` accept `is_template` field |
