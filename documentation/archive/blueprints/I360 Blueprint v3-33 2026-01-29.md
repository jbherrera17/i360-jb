## Executive Summary

Insight 360 is a **Values-Based AI Ecosystem** — a personal AI command center that aligns automated systems with organizational ethics. Version 3.33 delivers **Phase 50b: Role-Based Resource Assignment**, connecting business roles and departments to agents, actions, skills, and workflows so Execute 120 shows each user only resources appropriate for their role and department. It also adds **Platform Admin Impersonation** ("Act As"), allowing Synergi admins to view the platform as any user.

**Core Philosophy:** *"Technology should augment human brilliance—not replace it."*

## Phase 50b: Role-Based Resource Assignment (v3.33)

### What Was Completed

Phase 50b is the heart of Insight 360's differentiation — connecting the 5-level business role hierarchy and 6 departments to every resource type (agents, skills, actions, workflows) so Execute 120 delivers a personalized experience per user.

### Feature 1: Business Role Descriptions

Updated all 5 business role levels with 3 bullet point descriptions connecting each role to its responsibilities:

| Role | Level | Description |
|------|-------|-------------|
| **Executive** | 5 | Set vision/strategy, access all resources, approve budgets |
| **Director** | 4 | Lead department strategy, access strategic agents, manage OKRs |
| **Manager** | 3 | Orchestrate workflows, access content/reporting agents, track metrics |
| **Supervisor** | 2 | Execute workflows, access operational agents, monitor daily metrics |
| **IC** | 1 | Execute tasks with productivity agents, use assigned skills |

### Feature 2: New Junction Tables

Created 3 new junction tables for many-to-many resource-to-role/department mappings:

| Table | Purpose |
|-------|---------|
| `skill_roles` | Maps skills to minimum business role levels |
| `skill_departments` | Maps skills to departments with priority |
| `workflow_departments` | Maps workflows to multiple departments |

All tables include RLS policies (authenticated read, service role full access).

### Feature 3: Resource-Role-Department Seed Data

Comprehensive mappings connecting existing resources to roles and departments:

**Agent → Role Mappings:**
| Agent | Min Role | Rationale |
|-------|----------|-----------|
| First Principles Thinker | Manager | Strategic analysis |
| Strategic Advisor | Director | Executive-level counsel |
| All others | IC (unmapped) | Accessible to everyone |

**Agent → Department Mappings:**
| Agent | Departments |
|-------|-------------|
| Daily Briefer, Email Triager, Research Assistant, Meeting Prep | All 6 |
| Writing Coach | Marketing, Executive, Sales |
| Code Reviewer | Operations |
| First Principles Thinker | Executive, Operations, Finance |
| Strategic Advisor | Executive, Sales, Marketing, Operations |

**Skill → Role/Department:**
| Skill | Min Role | Departments |
|-------|----------|-------------|
| Weekly Article Package | Manager | Marketing, Executive |
| AI Article Formatter | IC | Marketing |
| Notion Calendar Sync | IC | Marketing, Operations |

**Workflow → Role/Department:**
| Workflow | Min Role | Departments |
|----------|----------|-------------|
| Thought Leadership Pipeline | Manager | Marketing, Executive |

### Feature 4: Execute 120 Skills & Role Filtering

Updated Execute 120 personalized cards endpoint with:
- New `getFilteredSkills()` function filtering by department and role junctions
- Updated `getFilteredActions()` with business role level filtering via `action_roles.role_level`
- Skills now returned in `/my-cards` response alongside agents, actions, workflows

### Feature 5: Generic `filterByBusinessRole()` Utility

Added reusable utility in `server/utils/resourceAccess.js` that any route can use to filter resources by the user's business role level.

### Feature 6: Platform Admin Impersonation ("Act As")

Allows Synergi platform admins to view the platform as any user:
- Start/stop impersonation via auth routes
- Impersonation state stored server-side with audit logging
- Auth middleware injects impersonated role/org
- Profile page shows org info and admin controls

## Access Control Layers

Version 3.33 extends to a **five-layer** access control system:

| Layer | Check | Applied To |
|-------|-------|------------|
| **1. Account Status** | active/suspended/inactive | Login gate |
| **2. Tier** | Organization's subscription tier | Module access |
| **3. Module** | can_access_module() RPC | Feature routes |
| **4. Visibility** | private/team/org/public | Resource filtering |
| **5. Role+Department** | business_role_levels + departments | Resource personalization |

**New in v3.33:** Layer 5 ensures Execute 120 shows only role-appropriate and department-relevant resources per user.
