## Executive Summary

Insight 360 is a **Values-Based AI Ecosystem** — a personal AI command center that aligns automated systems with organizational ethics. Version 3.71 delivers **Phase 71: Customer Support Agent System** — an optional paid add-on ($49-$399/mo by tier) providing AI-powered customer support with automated refund processing, smart escalation, tier management, and CSAT tracking. It includes: (1) **Database migration** with 6 new tables (`support_conversations`, `support_messages`, `support_actions`, `stripe_connections`, `slack_connections`, `widget_configs`); (2) **Policy service** evaluating refunds, escalations, and tier changes against configurable rules; (3) **AI agent service** with Anthropic `tool_use` loop (5 tools), conversation locking (FM-F003), action idempotency (FM-O008), TTL sweep (FM-F010), and metrics recording (FM-O013); (4) **15 API endpoints** across two route files; (5) **5 admin pages** (dashboard, conversations, conversation detail, actions queue, settings); (6) **53 automated tests**.

**Core Philosophy:** *"Technology should augment human brilliance—not replace it."*

## Phase 71: Customer Support Agent System (v3.71)

### What Was Completed

1. **Database Migration** (`db/phase71-support-system.sql`) — 6 new tables with RLS, atomic sequence generation via `next_support_message_seq()`, TTL sweep via `sweep_expired_support_actions()`, extended `check_org_limits()` for support_conversations, indexes, and seeds (3 support policies + module registration as `support_ai` beta add-on).

2. **Support Policy Service** (`server/services/supportPolicyService.js`) — Pure data service with 5-min TTL cache. Evaluates refund eligibility (amount/date/frequency rules), escalation triggers (sentiment/intent/failure/VIP), and tier changes (upgrade auto-approve, downgrade tenure check).

3. **Support Agent Service** (`server/services/supportAgentService.js`) — Core AI engine with `withConversationLock()` (in-process mutex via Promise chains), 5 Anthropic `tool_use` definitions (`lookup_customer`, `search_knowledge_base`, `process_refund`, `change_tier`, `escalate_to_human`), bounded tool loop (max 5 iterations), `metrics.recordLLMRequest()` on every LLM call, keyword-based intent classification (9 categories) and sentiment extraction (4 levels), guardrail screening, and fire-and-forget TTL sweep.

4. **Support Routes** (`server/routes/support.js`) — 10 endpoints: create conversation (with idempotency + resource limit check), list/get/update conversations, send message (triggers AI), SSE polling, manual escalation, resolve, CSAT submission, metrics dashboard. All gated by `requireModule('support_ai')`.

5. **Support Actions Routes** (`server/routes/supportActions.js`) — 5 endpoints: list actions, get action, approve (idempotent), deny (with reason), actions by conversation.

6. **Admin UI** — 5 HTML pages: Support Dashboard (stats + recent convos + pending actions), Support Conversations (filterable table + create), Conversation Detail (chat thread + customer sidebar + action log), Support Actions (approve/deny queue + stats), Support Settings (widget config + connections + policies).

7. **Tests & Documentation** — 53 tests (16 policy, 15 agent, 22 integration), user guide, help system registration.

## Phase 65: Integrity Dashboard Overhaul (v3.63)

### What Was Completed

Six sub-phases were completed:

1. **Alignment Audit — real scoring** (`server/services/ethicalContextService.js`) — `calculateIntegrityMetrics()` now calls `valuesAlignmentService.getAuditHistory()` to use real alignment scores when available, with graceful fallback to the existing chat-volume proxy.

2. **Counterfactual Value — industry baseline integration** (`server/services/ethicalContextService.js`) — The metrics engine now fetches `context_assets` with `asset_type='industry_baseline'`, parses financial impact strings via `parseFinancialImpact()`, and factors baseline coverage into the counterfactual value score.

3. **Trust Velocity — historical trend tracking** (`db/phase64-integrity-dashboard.sql`, `server/services/ethicalContextService.js`) — New `integrity_score_history` table stores periodic snapshots with RLS policies. Trend calculation compares current yield to the most recent prior snapshot.

4. **Expandable component cards** (`public/integrity.html`, `public/css/integrity-styles.css`) — All four component cards are now expandable with detail panels showing breakdown data.

5. **Industry Baseline in onboarding** (`public/soul-wizard.html`, `public/admin-org-settings.html`, `server/routes/soulConfig.js`) — Soul Wizard Step 6 now includes AI-powered industry baseline generation with Claude tool-use.

6. **Integrity Yield & period scoping** (`public/integrity.html`, `public/css/integrity-styles.css`) — Period selector (7/30/90 days) scopes all dashboard data.
