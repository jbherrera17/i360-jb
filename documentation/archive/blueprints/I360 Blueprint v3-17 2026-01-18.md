## Phase 36: Thought Leadership Enhancements (v3.17)

Two major features added to the Thought Leadership module:

### Feature 1: Article Image Generation

Automatic header image generation for thought leadership articles using DALL-E 3.

| Component | Description |
|-----------|-------------|
| **tlImageService.js** | New service for image generation and Supabase Storage upload |
| **5 Image Styles** | professional, abstract, illustrative, minimalist, futuristic |
| **GPT Prompt Optimization** | Uses GPT-4o-mini to generate optimal DALL-E prompts from article content |
| **Permanent Storage** | Images uploaded to Supabase Storage (DALL-E URLs expire after ~1 hour) |
| **Image History** | Track all generated images per calendar entry with version control |

#### New Endpoints

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/thought-leadership/images/styles` | GET | Get available image styles |
| `/api/thought-leadership/generate/image` | POST | Generate standalone image |
| `/api/thought-leadership/images/:entry_id` | GET | Get image history |
| `/api/thought-leadership/images/:entry_id/current/:image_id` | PUT | Set current image |

#### Package Integration

The `/generate/package` endpoint now includes optional Step 4: Image Generation

```
Step 1: Generate Article →
Step 2: Generate AI-Optimized Version →
Step 3: Generate 5 LinkedIn Posts →
Step 4: Generate Header Image (NEW, optional)
```

New request parameters:
- `generate_image` (boolean, default: true)
- `image_style` (string, default: 'professional')

### Feature 2: LinkedIn Publishing & Scheduling

Complete infrastructure for publishing content to LinkedIn with optimal time recommendations.

| Component | Description |
|-----------|-------------|
| **linkedinService.js** | OAuth 2.0 flow, token management, Share API integration |
| **oauth.js routes** | Authorization, callback, disconnect, and status endpoints |
| **Optimal Posting Times** | Algorithm recommends best times based on platform/content type |
| **Scheduled Publishing** | Queue and execute posts at scheduled times with retry logic |

#### OAuth Endpoints

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/oauth/linkedin/authorize` | GET | Start OAuth flow |
| `/api/oauth/linkedin/callback` | GET | Handle OAuth callback |
| `/api/oauth/linkedin/disconnect` | DELETE | Revoke connection |
| `/api/oauth/linkedin/status` | GET | Check connection status |
| `/api/oauth/connections` | GET | List all platform connections |

#### Publishing Endpoints

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/thought-leadership/publish/optimal-time` | GET | Get recommended posting time |
| `/api/thought-leadership/publish/schedule` | POST | Schedule future publication |
| `/api/thought-leadership/publish/now` | POST | Publish immediately |
| `/api/thought-leadership/publish/scheduled` | GET | List scheduled publications |
| `/api/thought-leadership/publish/:id` | DELETE | Cancel scheduled publication |
| `/api/thought-leadership/publish/history` | GET | Get publication history |

#### Optimal Posting Time Algorithm

Recommends posting times based on B2B engagement research:

| Platform | Content Type | Optimal Times |
|----------|--------------|---------------|
| LinkedIn | Article | Tue-Thu 8-9 AM |
| LinkedIn | Post | Tue-Wed 10-11 AM |
| LinkedIn | Any | Avoid: Fri PM, Weekends |

The `getOptimalPublishTime()` function returns:
- `recommendedTime` - Next optimal slot
- `reason` - Why this time is optimal
- `alternatives` - 2-3 alternative slots

Users can accept the recommendation or choose custom times.

## Database Schema (Phase 36)

New tables added in `db/phase36-tl-enhancements-schema.sql`:

### tl_image_generations

Stores image generation history with prompt tracking:

```sql
- id, user_id, calendar_entry_id
- prompt, revised_prompt (DALL-E's modification)
- image_url (permanent Supabase URL)
- model, size, quality, style
- is_current (boolean for version control)
```

### social_connections

OAuth connections for social platforms:

```sql
- id, user_id, platform
- access_token_encrypted, refresh_token_encrypted
- token_expires_at, scopes
- linkedin_person_urn, linkedin_org_urn
- status (active, expired, revoked, error)
```

### scheduled_publications

Publication queue with scheduling:

```sql
- id, user_id, calendar_entry_id
- platform, scheduled_at, timezone
- content_type, content_text, media_urls
- was_optimal_time, optimal_time_reason
- status (scheduled, publishing, published, failed, cancelled)
- retry_count, max_retries
```

### publication_history

Track published content with engagement metrics:

```sql
- id, user_id, platform
- published_at, published_url
- impressions, views, likes, comments, shares
- engagement_rate
```
