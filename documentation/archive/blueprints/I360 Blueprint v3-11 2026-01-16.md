## Phase 30: Radar Chart Visualization System (v3.11)

Added a comprehensive radar chart visualization system enabling agents to generate professional charts for technology assessments, capability comparisons, and risk analyses.

### Overview

The system provides three integration methods:
1. **QuickChart.io URL** - Embeddable chart images that work in any markdown renderer
2. **Chart.js Config** - Rich interactive charts rendered in the Insight 360 UI
3. **API Endpoints** - Server-side chart generation for agent post-processing

### Backend Service (`server/services/radarChartService.js`)

| Function | Description |
|----------|-------------|
| `generateQuickChartUrl()` | Creates embeddable QuickChart.io URLs |
| `generateChartJsConfig()` | Generates Chart.js configuration objects |
| `generateTechRadar()` | Technology assessment with 4 dimensions |
| `generateCapabilityRadar()` | Multi-entity capability comparison |
| `generateRiskRadar()` | Risk assessment visualization |
| `generateAsciiRadar()` | ASCII art fallback for plain text |
| `processAgentOutput()` | Auto-detects chart data from agent JSON |

### Technology Assessment Dimensions

| Dimension | Description | Score Range |
|-----------|-------------|-------------|
| **Maturity** | Production readiness, stability, ecosystem | 1-5 |
| **Relevance** | Strategic fit, use case alignment | 1-5 |
| **Capability Gap** | Internal readiness (inverted: 5 = ready) | 1-5 |
| **Risk Profile** | Overall risk level (inverted: 5 = low risk) | 1-5 |

### API Endpoints (`server/routes/visualizations.js`)

| Method | Route | Description |
|--------|-------|-------------|
| POST | `/api/visualizations/radar` | Generic radar chart |
| POST | `/api/visualizations/tech-radar` | Technology assessment radar |
| POST | `/api/visualizations/capability` | Capability comparison radar |
| POST | `/api/visualizations/risk` | Risk assessment radar |
| POST | `/api/visualizations/process` | Auto-detect from agent output |
| GET | `/api/visualizations/colors` | Available color palettes |
| GET | `/api/visualizations/tech-radar/options` | Ring and quadrant options |

### Frontend Component (`public/js/charts/radarChart.js`)

| Method | Description |
|--------|-------------|
| `RadarChart.render()` | Render chart in container |
| `RadarChart.renderTechRadar()` | Technology assessment chart |
| `RadarChart.renderCapabilityRadar()` | Capability comparison chart |
| `RadarChart.init()` | Auto-detect charts in chat messages |
| `RadarChart.parseChartData()` | Extract chart data from content |

### Technology Radar Framework

**Maturity Rings:**
| Ring | Meaning | Action |
|------|---------|--------|
| **ADOPT** | Proven, production-ready | Use confidently, scale up |
| **TRIAL** | Promising, worth investing | Build capability, run pilots |
| **ASSESS** | Interesting, needs exploration | Research, prototype, evaluate |
| **HOLD** | Caution advised | Avoid new investment, monitor |

**Quadrants:**
| Quadrant | Focus Areas |
|----------|-------------|
| **AI/ML** | Foundation models, fine-tuning, prompt engineering, agents |
| **Platforms** | LLM providers, AI dev platforms, MLOps, integrations |
| **Languages** | Programming languages, ML frameworks, APIs, SDKs |
| **Patterns** | Architecture patterns, dev practices, governance, security |

### Agent Integration

Agents can output radar charts by including a JSON block:

```json
{
  "radar_chart": {
    "type": "radar",
    "data": {
      "labels": ["Maturity", "Relevance", "Capability", "Low Risk"],
      "datasets": [{
        "label": "Technology Name",
        "data": [4, 5, 3, 4]
      }]
    }
  }
}
```

Or use QuickChart URL in markdown:
```markdown
![Assessment](https://quickchart.io/chart?c={type:'radar',data:{...}})
```

## Phase 29: Agent Context Mapping Bug Fix (v3.10)

Critical bug fix for agent context mapping functionality that was failing with RLS policy violations.

### Root Cause Analysis

Two issues were identified:

1. **Schema Mismatch** - The API route was attempting to INSERT columns that don't exist in the `agent_context_mappings` table:
   - `trigger_keywords` (non-existent)
   - `trigger_regex` (non-existent)
   - `truncation_strategy` (non-existent)

2. **RLS Policy Misconfiguration** - The table had 10 duplicate/conflicting RLS policies where "service_role" policies were incorrectly assigned to `PUBLIC` (`{-}`) instead of the actual `service_role` role.

### Fix Applied

**API Route Fix** (`server/routes/agents.js`):
```javascript
// Before (broken)
const { asset_id, injection_mode, priority, trigger_keywords,
        trigger_regex, max_tokens, truncation_strategy } = req.body;

// After (fixed)
const { asset_id, injection_mode, priority, max_tokens } = req.body;
```

**RLS Policy Fix** (`db/phase27-security-fixes.sql`):
- Dropped all 10 duplicate/broken policies
- Created 5 clean policies with proper role assignments
