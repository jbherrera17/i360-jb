# Insight 360 Blueprint v3.0

**Version:** 3.0
**Date:** January 9, 2026
**Status:** Planning | SynergiNexus & Role-Based Architecture
**Codename:** Governance
**Previous Version:** v2.39 (Phase 19.2)

---

## Executive Summary

Insight 360 v3.0 introduces **SynergiNexus** — a values-driven intelligence governance system that ensures all AI interactions are disciplined, ethical, and aligned with organizational values. This major release also implements a **role-based user model** with tag-based resource matching, transforming Execute 120 into a personalized, department-aware experience.

**Core Philosophy:** *"Intelligence without governance amplifies noise. Disciplined intelligence amplifies discernment."*

### Disciplined Intelligence Governance Model (DIGM)

The DIGM defines **how** AI thinks and responds through four governance layers:

#### Layer 1 — Identity (Configurable at Onboarding)

Defines who the AI is:
- Role: Disciplined thinking partner
- Authority boundary: Advisory only
- Ethical posture: Consequence-aware, non-manipulative
- Orientation: Systems-level, long-term aware

#### Layer 2 — Cognitive Discipline (Configurable at Onboarding)

Defines how reasoning must occur:

1. Context and assumptions
2. Problem decomposition
3. Step-by-step reasoning
4. Alternatives and trade-offs
5. Synthesis toward understanding or decision support

#### Layer 3 — Voice & Expression (Constrained)

Defines how intelligence is communicated:

**Allowed:** Calm, Grounded, Deliberate, Clear

**Prohibited:** Alarmist, Hype-driven, Manipulative, Performatively confident

#### Layer 4 — Contextual Adaptation (Bounded)

Defines what may flex without breaking integrity:

**Adaptable:** Depth of explanation, Examples/metaphors, Vocabulary, Challenge vs. affirmation

**Not Adaptable:** Identity, Ethical posture, Reasoning order, Authority boundary

### Values → Principles Translation

Values are client-defined inputs that shape the system through enforceable constraints:

```
CLIENT VALUES
    │
    ▼
VALUES → PRINCIPLES MODULE
(Constraints & Non-Negotiables)
    │
    ▼
ROLE OVERLAYS
[ Executive | Manager | IC ]
    │
    ▼
AI AGENTS & APPLICATIONS
    │
    ▼
HUMAN DECISION-MAKER
(Authority Retained)
```

### Conflict Resolution Escalation Model

| Severity | Resolver | Examples |
|----------|----------|----------|
| Low | Department Admin | Single-value interpretation |
| Medium | Department Admin | Department-scoped conflicts |
| High | System Admin | Cross-department conflicts |
| Critical | superAdmin | Organization-wide value conflicts |

### Governance Enforcement

| Stage | Action |
|-------|--------|
| **Pre-Injection** | Inject DIGM rules, values, principles as system context before LLM call |
| **Post-Validation** | Validate response compliance with voice/expression rules, flag conflicts |

### Tag Categories

| Category | Purpose | Examples |
|----------|---------|----------|
| **skill** | What capability is needed | writing, analytics, design, coding |
| **domain** | What business area | marketing, finance, HR, sales |
| **function** | What activity | content-creation, reporting, planning |

### Tag Matching Algorithm

```
1. Get user's roles → user_roles
2. Get tags for those roles → role_tags
3. Get user's responsibilities → user_responsibilities
4. Get tags for those responsibilities → responsibility_tags
5. Combine all tags (union)
6. Match agents where agent_tags ∩ user_tags ≠ ∅
7. Match workflows where workflow_tags ∩ user_tags ≠ ∅
8. Include parent tag matches (hierarchical inheritance)
```

| Role | Capabilities |
|------|--------------|
| **superAdmin** | DIGM config, global tags, system templates, SynergiNexus governance, escalation rules, company onboarding |

## Database Schema Changes

### New Tables

```sql
-- ============================================
-- TAGS (Categorized with Hierarchy)
-- ============================================
CREATE TABLE tags (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    category TEXT NOT NULL CHECK (category IN ('skill', 'domain', 'function')),
    parent_id UUID REFERENCES tags(id) ON DELETE SET NULL,
    description TEXT,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- ============================================
-- DEPARTMENT ROLES (Templates + Custom)
-- ============================================
CREATE TABLE department_roles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    department_id UUID REFERENCES departments(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    description TEXT,
    role_level TEXT NOT NULL DEFAULT 'ic'
        CHECK (role_level IN ('ic', 'manager', 'director', 'vp', 'c-level')),
    is_system_template BOOLEAN DEFAULT false,
    is_active BOOLEAN DEFAULT true,
    sort_order INTEGER DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- ============================================
-- ROLE TAGS (Many-to-Many)
-- ============================================
CREATE TABLE role_tags (
    role_id UUID REFERENCES department_roles(id) ON DELETE CASCADE,
    tag_id UUID REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (role_id, tag_id)
);

-- ============================================
-- RESPONSIBILITIES (Hierarchical)
-- ============================================
CREATE TABLE responsibilities (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    description TEXT,
    parent_id UUID REFERENCES responsibilities(id) ON DELETE SET NULL,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- ============================================
-- ROLE RESPONSIBILITIES (Many-to-Many)
-- ============================================
CREATE TABLE role_responsibilities (
    role_id UUID REFERENCES department_roles(id) ON DELETE CASCADE,
    responsibility_id UUID REFERENCES responsibilities(id) ON DELETE CASCADE,
    PRIMARY KEY (role_id, responsibility_id)
);

-- ============================================
-- RESPONSIBILITY TAGS (Many-to-Many)
-- ============================================
CREATE TABLE responsibility_tags (
    responsibility_id UUID REFERENCES responsibilities(id) ON DELETE CASCADE,
    tag_id UUID REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (responsibility_id, tag_id)
);

-- ============================================
-- USER ROLES (Many-to-Many - Multiple Roles)
-- ============================================
CREATE TABLE user_roles (
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    role_id UUID REFERENCES department_roles(id) ON DELETE CASCADE,
    is_primary BOOLEAN DEFAULT false,
    assigned_at TIMESTAMPTZ DEFAULT NOW(),
    PRIMARY KEY (user_id, role_id)
);

-- ============================================
-- USER RESPONSIBILITIES (Selected from Role)
-- ============================================
CREATE TABLE user_responsibilities (
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    responsibility_id UUID REFERENCES responsibilities(id) ON DELETE CASCADE,
    PRIMARY KEY (user_id, responsibility_id)
);

-- ============================================
-- AGENT TAGS (Many-to-Many)
-- ============================================
CREATE TABLE agent_tags (
    agent_id UUID REFERENCES agents(id) ON DELETE CASCADE,
    tag_id UUID REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (agent_id, tag_id)
);

-- ============================================
-- WORKFLOW TAGS (Many-to-Many)
-- ============================================
CREATE TABLE workflow_tags (
    workflow_id UUID REFERENCES workflows(id) ON DELETE CASCADE,
    tag_id UUID REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (workflow_id, tag_id)
);

-- ============================================
-- SYNERGINEXUS GOVERNANCE TABLES
-- ============================================

-- DIGM Configuration
CREATE TABLE digm_config (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    layer TEXT NOT NULL CHECK (layer IN ('identity', 'cognitive', 'voice', 'adaptation')),
    config_key TEXT NOT NULL,
    config_value JSONB NOT NULL,
    is_active BOOLEAN DEFAULT true,
    created_by UUID REFERENCES users(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE (layer, config_key)
);

-- Values Definition
CREATE TABLE governance_values (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    plain_meaning TEXT,
    why_it_matters TEXT,
    is_non_negotiable BOOLEAN DEFAULT false,
    is_active BOOLEAN DEFAULT true,
    created_by UUID REFERENCES users(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Principles (translated from values)
CREATE TABLE governance_principles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    value_id UUID REFERENCES governance_values(id) ON DELETE CASCADE,
    statement TEXT NOT NULL,
    constraint_type TEXT NOT NULL
        CHECK (constraint_type IN ('prohibition', 'requirement', 'disclosure', 'boundary')),
    applies_when TEXT,
    digm_touchpoint TEXT CHECK (digm_touchpoint IN ('context', 'decomposition', 'reasoning', 'alternatives', 'synthesis')),
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Conflict Log
CREATE TABLE governance_conflicts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID REFERENCES conversations(id),
    agent_id UUID REFERENCES agents(id),
    conflict_description TEXT NOT NULL,
    values_involved UUID[] DEFAULT '{}',
    severity TEXT NOT NULL CHECK (severity IN ('low', 'medium', 'high', 'critical')),
    status TEXT NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending', 'escalated', 'resolved', 'dismissed')),
    resolved_by UUID REFERENCES users(id),
    resolution_notes TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    resolved_at TIMESTAMPTZ
);

-- Escalation Rules
CREATE TABLE escalation_rules (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    severity TEXT NOT NULL CHECK (severity IN ('low', 'medium', 'high', 'critical')),
    resolver_level TEXT NOT NULL
        CHECK (resolver_level IN ('department_admin', 'system_admin', 'super_admin')),
    auto_escalate_after_hours INTEGER DEFAULT 24,
    notification_channels JSONB DEFAULT '["email"]',
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## Migration Strategy

### Breaking Changes

1. **User model** - Users now require role assignments
2. **Execute 120** - Will show empty if user has no roles/tags
3. **Agent access** - Agents need tags to be discoverable

### Migration Steps

1. Create new tables (non-destructive)
2. Seed default role templates
3. Seed initial tag taxonomy
4. Migrate existing users to default "IC" role in their department
5. Tag existing agents with relevant domain tags
6. Enable personalized Execute 120

### Rollback Plan

- All new tables are additive (no existing tables modified destructively)
- Feature flags can disable tag-based filtering
- Execute 120 can fall back to showing all agents/workflows
