## Executive Summary

Insight 360 is a **Values-Based AI Ecosystem** — a personal AI command center that aligns automated systems with organizational ethics. Version 3.59 delivers **Phase 61c**, a multi-tenant data isolation sweep and workflow execution fix: (1) **Parthenon API org-scoping** — departments, roles, OKRs, and processes now filter by org_id so admins only see their own organization's data; (2) **sample dashboard templates** for new orgs on Company Dashboard and Integrity Dashboard showing preview data until real data is entered; (3) **department editing fix** replacing `.single()` with `.maybeSingle()` across Parthenon and department routes to eliminate "Cannot coerce to single JSON object" errors; (4) **workflow execution saving** via a missing POST /executions endpoint; (5) **workflow run naming** with a new `name` column on `workflow_executions` and a naming UI on the completion screen; (6) **x-org-id header propagation** added to 6 frontend pages (company-dashboard, integrity, parthenon, admin-departments, workflow-builder, workflow-run).

## Phase 61c: Org-Scoped Dashboards, Department Editing Fixes & Workflow Execution Saving (v3.59)

### What Was Completed

Seven deliverables were completed in this phase:

1. **Parthenon API org-scoping** (`server/routes/parthenon.js`) — Added `resolveOrgId()` helper (reads x-org-id header, falls back to user's default_org_id) and `getOrgDepartmentIds()` helper. All four GET endpoints (departments, roles, OKRs, processes) now filter by org_id. Departments filter directly via `.eq('org_id', orgId)`; roles, OKRs, and processes filter via department_id IN (org's departments). POST /departments now sets org_id. PUT handlers backfill org_id on legacy records with NULL org_id.

2. **Company Dashboard sample template** (`public/company-dashboard.html`) — When an org has zero departments, a sample template renders showing 3 example departments, 4 OKRs with varying health scores, a scorecard preview, and a "Needs Attention" section. A banner explains this is preview data.

3. **Integrity Dashboard sample data** (`public/integrity.html`) — Updated sampleData from all-zeros to meaningful demo values (Integrity Yield: 78, Trust Velocity: 85, Intervention Effectiveness: 82, Alignment Audit: 68, Counterfactual Value: 75). Enhanced empty state with sample ring chart and component scores.

4. **Department editing fix** (`server/routes/parthenon.js`, `server/routes/departments.js`) — All PUT handlers changed from `.single()` to `.maybeSingle()` with proper 404 handling. This eliminates the "Cannot coerce the result to a single JSON object" error when updating departments or Parthenon entities as org admins.

5. **x-org-id header propagation** (6 frontend files) — Added `getHeaders()` helper functions to `company-dashboard.html`, `integrity.html`, `parthenon.html`, `admin-departments.html`, `workflow-builder.html`, and `workflow-run.html`. All fetch calls now include auth token and x-org-id from localStorage.

6. **Workflow execution saving** (`server/routes/execute120.js`) — Added missing `POST /api/execute120/executions` endpoint that `workflow-run.html` calls to create execution records. This was the root cause of workflows not saving.

7. **Workflow run naming** (`db/phase61c-workflow-execution-name.sql`, `server/routes/execute120.js`, `public/workflow-run.html`) — Added `name` column to `workflow_executions` table. PUT /executions now accepts `name`. Completion screen shows a name input (defaulting to "Workflow Name - Date") with Save button.
