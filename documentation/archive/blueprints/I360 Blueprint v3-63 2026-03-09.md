## Executive Summary

Insight 360 is a **Values-Based AI Ecosystem** — a personal AI command center that aligns automated systems with organizational ethics. Version 3.63 delivers **Phase 65: Integrity Dashboard Overhaul** — a comprehensive rebuild of the Integrity Dashboard that connects real data sources to all four integrity components, replacing proxy formulas with live service calls: (1) **Alignment Audit** now uses `valuesAlignmentService` for real values-alignment scoring instead of the chat-volume proxy; (2) **Counterfactual Value** fetches and parses industry baseline financial data from `context_assets`; (3) **Trust Velocity** tracks historical scores via a new `integrity_score_history` table for real trend calculations; (4) all four component cards are now **expandable with detail panels**; (5) a **period selector** (7/30/90 days) scopes all dashboard data; (6) **AI-powered industry baseline generation** is integrated into the Soul Wizard using Claude tool-use; (7) **Industry Baseline** is added to the onboarding checklist.

**Core Philosophy:** *"Technology should augment human brilliance—not replace it."*

## Phase 65: Integrity Dashboard Overhaul (v3.63)

### What Was Completed

Six sub-phases were completed:

1. **Alignment Audit — real scoring** (`server/services/ethicalContextService.js`) — `calculateIntegrityMetrics()` now calls `valuesAlignmentService.getAuditHistory()` to use real alignment scores when available, with graceful fallback to the existing chat-volume proxy for orgs that haven't completed Align 120. The `isRealScore` flag is returned so the frontend can indicate data source.

2. **Counterfactual Value — industry baseline integration** (`server/services/ethicalContextService.js`) — The metrics engine now fetches `context_assets` with `asset_type='industry_baseline'`, parses financial impact strings via `parseFinancialImpact()` (handles "$3.7B", "£450M", "€2 billion", etc.), and factors baseline coverage into the counterfactual value score with a `baselineCoverageBonus` (up to +20 points based on entry count).

3. **Trust Velocity — historical trend tracking** (`db/phase64-integrity-dashboard.sql`, `server/services/ethicalContextService.js`) — New `integrity_score_history` table stores periodic snapshots with RLS policies. Snapshots are saved fire-and-forget (throttled to max once per hour per org/period). Trend calculation compares current yield to the most recent prior snapshot, replacing the hardcoded `+0%`.

4. **Expandable component cards** (`public/integrity.html`, `public/css/integrity-styles.css`) — All four component cards (Trust Velocity, Intervention Effectiveness, Alignment Audit, Counterfactual Value) are now expandable with detail panels showing breakdown data: resolution rates, review completion, per-value alignment scores, financial impact breakdowns. Consistent expand/collapse UX with `aria-expanded` accessibility.

5. **Industry Baseline in onboarding** (`public/soul-wizard.html`, `public/admin-org-settings.html`, `server/routes/soulConfig.js`) — Soul Wizard Step 6 (Domain) now includes an "Industry Baseline" section with a "Generate with AI" button. The `POST /api/soul-config/generate-industry-baseline` endpoint uses Claude (Haiku 4.5) with forced tool-use to generate 5-8 real, verifiable industry integrity incidents. Users review and can remove entries before publishing. Entries are saved to `context_assets` on publish. The onboarding checklist adds a "recommended" tier item for Industry Baseline Data.

6. **Integrity Yield & period scoping** (`public/integrity.html`, `public/css/integrity-styles.css`) — Period selector (7/30/90 days) scopes all dashboard data including metrics, close call log, and leading indicators. Real trend data wired from `metrics.trend`. Leading indicators use real alignment data when available.

## Phase 64: Branding System Fix & Font Unification (v3.62)

### What Was Completed

Three deliverables were completed in this phase:

1. **auth-fetch.js Content-Type fix** (`public/js/auth-fetch.js`) — The global `authFetch()` function was missing the `Content-Type: application/json` header, causing Express to ignore request bodies on all PUT/POST requests routed through the global fetch wrapper.

2. **Branding save endpoint hardening** (`server/routes/orgCustomization.js`) — Switched from `.upsert()` to `.update().eq('org_id')` with `req.body` cloning.

3. **Platform-wide font unification** (51 HTML files, 4 CSS files, 4 JS files) — Replaced 155+ hardcoded `font-family` declarations with CSS custom properties.
