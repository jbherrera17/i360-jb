## Phase 59d: Fix Invitation Auth Flow & Direction Modal Updates (v3.54)

### What Was Completed

The invitation system had a critical bug: the `/api/auth/accept-invite` endpoint was missing from the `publicPaths` list in the authentication middleware. This meant that in production, when a newly invited user clicked their activation link and tried to set a password, the API call was rejected with a 401 "Authentication required" error before the route handler ever ran. Since the user had no auth cookie (they were brand new), they could never complete activation, leaving their status permanently stuck as `'invited'` — which the login flow explicitly blocks.

Additionally, the post-login direction modal was updated to replace the "Profile" navigation button with "Higgins" (the AI chat assistant), and the Sign Out button was enabled (it was previously disabled when the modal opened).

### 1. Invitation Auth Flow Fix (Critical Bug)

The authentication middleware in `server/middleware/auth.js` maintains a `publicPaths` array of endpoints that don't require authentication. The `/api/auth/accept-invite` endpoint was missing from this list:

| Before (Broken) | After (Fixed) |
|-----------------|---------------|
| `publicPaths` did not include `/api/auth/accept-invite` | `/api/auth/accept-invite` added to `publicPaths` |

**Impact chain of the bug:**
1. Admin invites user → email sent, `public.users` record created with `status: 'invited'`
2. User clicks activation link → lands on `login.html`, sees password form
3. User submits password → `POST /api/auth/accept-invite` → **401 rejected** by middleware
4. Activation never completes → status stays `'invited'` permanently
5. Login checks status → blocks anything not `'active'` → **user can never log in**
6. Manually changing role/password via admin UI doesn't change the `status` field → still blocked

### 2. Direction Modal Updates

The post-login direction modal (`public/js/direction-modal.js`) was updated:

| Change | Before | After |
|--------|--------|-------|
| **First button (Admin)** | Profile (`/profile.html`, `user` icon) | Higgins (`/chat.html`, `message-circle` icon) |
| **First button (User)** | Profile (`/profile.html`, `user` icon) | Higgins (`/chat.html`, `message-circle` icon) |
| **Sign Out button** | Disabled on modal open (`disabled = true`, `classList.add('disabled')`) | Enabled and functional |

### 3. Modal Test Page Updates

Updated direction modal test log messages in `modal-test.html` to reflect the new "Higgins" button label.
