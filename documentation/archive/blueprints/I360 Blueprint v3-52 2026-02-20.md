## Phase 59b: Responsive Navigation, Admin UX & Invitation Flow Improvements (v3.52)

### What Was Completed

The platform was desktop-only — no mobile or tablet navigation existed. The sidebar was inaccessible on viewports under 1024px, making the app unusable on phones and iPads. Additionally, the platform admin users table showed limited information, the invitation acceptance flow only supported the legacy implicit token format (breaking on newer Supabase PKCE flows), and Research Studios had no delete functionality.

Phase 59b addresses all of these with:

### 1. Responsive Mobile Navigation (Single Source of Truth)

A complete responsive navigation system built into `navigation.js` as the single source of truth — no HTML pages were touched.

| Viewport | Sidebar Behavior | Hamburger | Collapsed State |
|----------|-----------------|-----------|-----------------|
| > 1024px (desktop) | Fixed, always visible | Hidden | Icon-only (72px) supported |
| 768–1024px (tablet) | Overlay, slide-in | Visible (top-left) | Cancelled — full width when open |
| < 768px (phone) | Overlay, narrowed | Visible (top-left) | Same as tablet |

**Key Features:**
- Hamburger button auto-injected by `navigation.js` — no per-page HTML changes needed
- 44px touch targets (WCAG 2.5.5 compliant)
- Backdrop overlay with blur, close on tap or Escape key
- Auto-close on nav link click with 100ms delay
- Body scroll lock when menu is open
- Aria attributes (`aria-expanded`, `aria-label`, `aria-controls`) for accessibility
- Lucide icon swap between `menu` and `x` on toggle

**Business Rules:**
1. Never add a hamburger button to HTML pages — `navigation.js` injects it automatically
2. Edit nav structure only in `navConfig` — changes propagate to both desktop and mobile
3. If adding new `.sidebar-collapsed` CSS, mirror the reset in `@media (max-width: 1024px)`
4. Maintain 44px minimum touch target on the hamburger button

### 2. Platform Admin Users Table Enhancement

The users table in `admin-platform.html` was expanded from 6 columns to 8 with richer data:

| Column | Description |
|--------|-------------|
| User | Name + email (unchanged) |
| Organization | First org name with +N tooltip for multiple |
| Client | Client name for agency orgs, dash for others |
| Role | Platform Admin badge or org member role |
| Tier | Color-coded subscription tier badge |
| Portal | Client portal access indicator |
| Status | Color-coded active/invited/suspended badge |
| Actions | Resend invite, reset password, etc. |

### 3. Invitation Flow PKCE Support

Supabase's newer PKCE flow sends `?token_hash=X&type=invite` instead of `#access_token=X`. The accept-invite flow now supports both:
- **Legacy implicit flow:** `access_token` + `refresh_token` in URL hash
- **New PKCE flow:** `token_hash` exchanged via `supabase.auth.verifyOtp()`

### 4. Onboarding Checklist Inline Actions

The "Invite Team Members" checklist item now opens an inline invite modal instead of navigating away to `admin-org-members.html`. Uses ModalService with email + role fields, calls the invite API directly, and refreshes the checklist on success.

### 5. Research Studio Improvements

- **Studio deletion:** Delete button on studio cards with confirmation modal
- **Layout fix:** Replaced fixed `height: calc(100vh - var(--header-height))` with `flex: 1; min-height: 0` for proper flex layout
- **Result panel fix:** Removed `min-width: 400px` that caused horizontal overflow
- **Drag-and-drop guard:** `setupDragAndDrop()` now checks for upload zone existence

### 6. Admin Session Handling

Admin user deletion now checks for 401 status and shows a clear "session expired" error instead of a generic failure message.
