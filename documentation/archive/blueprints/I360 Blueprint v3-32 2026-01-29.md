## Phase 50: Database Security Hardening (v3.32)

### What Was Completed

Phase 50 resolves all Supabase database linter security warnings — 27 views defined with `SECURITY DEFINER` converted to `SECURITY INVOKER`, and 2 tables missing Row Level Security (RLS) policies remediated. Additionally, 9 views referencing non-existent tables were cleaned up.

### Feature 1: SECURITY INVOKER View Migration

Converted 18 views from `SECURITY DEFINER` to `SECURITY INVOKER`, ensuring queries execute with the calling user's permissions rather than the view owner's:

### Schema Corrections During Migration

Several view definitions extracted from `pg_get_viewdef()` referenced columns or tables that had drifted from actual schema. All were corrected:

| Issue | Fix |
|-------|-----|
| `briefing_configs.is_active` | Changed to `is_enabled` |
| `briefing_agents` table | Replaced with `briefing_sections` join |
| `client_report_shares.report_type` | Replaced with actual columns (`session_report_id`, `shared_by`, etc.) |
| `client_users.full_name` | Changed to `name AS full_name` |
| `company_profiles.website` | Removed (column doesn't exist) |
| `org_members` table | Changed to `organization_members` |
| `subscription_tiers.display_name` | Changed to `name` |
| `auth.users.full_name` | Changed to `raw_user_meta_data->>'full_name'` |
| `auth.users.avatar_url` | Changed to `raw_user_meta_data->>'avatar_url'` |
| `organization_members.business_role` | Joined `users` table for `business_role` |
| `organization_members.department_id` | Joined `users` table for `department_id` |
| `context_assets.is_active` | Changed to `is_current` |
| `*.visibility = 'org_wide'` | Changed to `'organization'` |
| `workflows.visibility` | Changed to `is_public` (no visibility column) |
