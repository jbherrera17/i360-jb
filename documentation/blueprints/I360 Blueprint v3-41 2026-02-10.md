## Phase 54g: Roles & Setup Progress Bug Fixes (v3.41)

### What Was Completed

Fixed multiple interconnected bugs in the roles management page and organization settings setup progress panel. The roles page had stale filter values that didn't match the database schema, and the org settings page was calling a non-existent API endpoint for roles data.

### Bug Fixes

| File | Issue | Fix |
|------|-------|-----|
| `public/roles.html` | Level filter dropdown had `executive`/`supervisor` values that don't exist in database | Replaced with correct values: `ic`, `manager`, `director`, `vp`, `c-level` |
| `public/roles.html` | `populateDepartmentFilters()` tried to access `#role-department` (modal-only element), throwing error that prevented `#department-filter` from populating | Removed modal element reference; added null guard |
| `public/roles.html` | `formatLevel()` mapped to stale labels (e.g., `ic` → "IC") | Updated to match edit form labels (e.g., `ic` → "Individual Contributor") |
| `public/admin-org-settings.html` | Setup progress fetched `/api/department-roles` but route is mounted at `/api/roles` | Changed to `/api/roles` — "Roles Defined" card now shows configured status |

### Documentation Updates

| File | Change |
|------|--------|
| `documentation/guides/New Clients/platform-setup-process.md` | v2.1: Replaced checkbox list with detailed table showing all 8 setup progress items with check logic, API sources, and navigation links |

### Root Cause

The level filter and `formatLevel()` were written with placeholder values during initial development and never updated when the database schema finalized the `role_level` CHECK constraint (`ic`, `manager`, `director`, `vp`, `c-level`). The department filter bug was a DOM timing issue — the function assumed both the page filter and modal select existed simultaneously. The setup progress API mismatch occurred when the route was renamed from `department-roles` to `roles` but the org settings page wasn't updated.
