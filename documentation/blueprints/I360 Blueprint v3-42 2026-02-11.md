## Phase 54h: Voice I/O, LLM Updates & Node.js 24 Compatibility (v3.42)

### What Was Completed

Added complete voice input/output capabilities to the Higgins chat interface, enabling users to speak messages via microphone (transcribed by OpenAI STT) and hear AI responses read aloud (via OpenAI TTS). Added a comprehensive Voice admin tab in Platform Admin for controlling voice features. Updated the LLM registry with the latest models from OpenAI (GPT-5.3 Codex, o3, o3-pro, o4-mini). Fixed two critical Node.js 24 compatibility issues that prevented the server from starting.

| Issue | Root Cause | Fix |
|-------|-----------|-----|
| **Server startup hang (Winston)** | `readable-stream` v2.3.8 (Winston dependency) hangs on Node.js 24 | Replaced Winston with native console-based logger maintaining identical API |
| **Server startup hang (jsdom)** | `require('jsdom')` hangs due to ESM parse5 dependency on Node.js 24 | Made jsdom lazy-loaded in `sourceProcessor.js`, only loaded when processing HTML |

## Voice I/O Architecture

```
User clicks mic → getUserMedia → MediaRecorder (webm/opus)
    → FormData POST /api/chat/voice/transcribe
        → multer (memory, 10MB) → voice.transcribe()
            → openai.transcribeAudio() → File wrapper → OpenAI API
        → Response: { text: "transcribed text" }
    → Insert text into chat input

User clicks play → POST /api/chat/voice/tts
    → voice.speak() → openai.textToSpeech() → OpenAI API
    → Response: audio/mpeg binary
    → new Audio(blob URL) → play()

Admin config: platform_config.feature_flags.voice
    → GET /api/chat/voice/config → frontend respects enabled/defaults
```
