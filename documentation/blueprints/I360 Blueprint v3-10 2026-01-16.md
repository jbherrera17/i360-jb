## Phase 29: Agent Context Mapping Bug Fix (v3.10)

Critical bug fix for agent context mapping functionality that was failing with RLS policy violations.

### Root Cause Analysis

Two issues were identified:

1. **Schema Mismatch** - The API route was attempting to INSERT columns that don't exist in the `agent_context_mappings` table:
   - `trigger_keywords` (non-existent)
   - `trigger_regex` (non-existent)
   - `truncation_strategy` (non-existent)

2. **RLS Policy Misconfiguration** - The table had 10 duplicate/conflicting RLS policies where "service_role" policies were incorrectly assigned to `PUBLIC` (`{-}`) instead of the actual `service_role` role.

### Fix Applied

**API Route Fix** (`server/routes/agents.js`):
```javascript
// Before (broken)
const { asset_id, injection_mode, priority, trigger_keywords,
        trigger_regex, max_tokens, truncation_strategy } = req.body;

// After (fixed)
const { asset_id, injection_mode, priority, max_tokens } = req.body;
```

**RLS Policy Fix** (`db/phase27-security-fixes.sql`):
- Dropped all 10 duplicate/broken policies
- Created 5 clean policies with proper role assignments:
  - `acm_select` → `authenticated`
  - `acm_insert` → `authenticated`
  - `acm_update` → `authenticated`
  - `acm_delete` → `authenticated`
  - `acm_service_role` → `service_role` (FOR ALL with USING true)

### Verification

Policies now correctly show:
```json
{ "polname": "acm_service_role", "polcmd": "*", "polroles": "{service_role}" }
```

### Files Modified

- `server/routes/agents.js` - Removed non-existent columns from INSERT
- `db/phase27-security-fixes.sql` - Added proper RLS policies for agent_context_mappings

## Phase 16: Reliability & Resilience (v2.33)

Implemented production-grade reliability patterns for graceful degradation and automatic recovery.

### Retry with Exponential Backoff

| Option | Default | Description |
|--------|---------|-------------|
| `maxRetries` | 3 | Maximum retry attempts |
| `initialDelayMs` | 1000 | Initial delay before first retry |
| `maxDelayMs` | 30000 | Maximum delay cap |
| `backoffMultiplier` | 2 | Exponential multiplier |
| `jitterFactor` | 0.1 | Random jitter (±10%) |

**Retryable Conditions:**
- Network errors: `ECONNRESET`, `ETIMEDOUT`, `ECONNREFUSED`, `EPIPE`, `ENOTFOUND`
- HTTP status codes: 408, 429, 500, 502, 503, 504
- Message patterns: Rate limit, Overloaded (Claude-specific)

### Circuit Breaker Pattern

| State | Description | Behavior |
|-------|-------------|----------|
| `CLOSED` | Normal operation | Requests pass through |
| `OPEN` | Service failing | Requests rejected immediately |
| `HALF_OPEN` | Testing recovery | Limited requests allowed |

**Configuration:**
- `failureThreshold`: 5 failures to open circuit
- `successThreshold`: 2 successes to close from half-open
- `timeout`: 30000ms before recovery attempt

**Health Endpoints:**
- `GET /api/health/circuits` - Circuit breaker statuses
- `POST /api/health/circuits/reset` - Reset all circuit breakers

**Files Created:**
- `server/services/reliability.js` - Retry, circuit breaker, timeout, fallback utilities
- `__tests__/unit/services/reliability.test.js` - 50 tests
