## Phase 62: Open Brain MCP Integration (v3.61)

### What Was Completed

Six deliverables were completed in this phase:

1. **Open Brain MCP service** (`server/services/openBrainService.js`) — Node.js native HTTP client implementing MCP Streamable HTTP transport (JSON-RPC 2.0 over SSE). Connects to `open-brain-mcp` Supabase Edge Function. Auth via `?key=` query parameter. Parses SSE response format (`event: message\ndata: {...}`). Exports: `isConfigured()`, `captureThought(content)`, `searchThoughts(query, options)`, `listThoughts(filters)`, `thoughtStats()`.

2. **Open Brain REST API** (`server/routes/openBrain.js`) — 5 endpoints registered at `/api/open-brain/`: `GET /status` (health check + stats), `POST /capture` (save a thought), `GET /search?q=` (semantic search with limit/threshold params), `GET /thoughts` (list with type/topic/person/days filters), `GET /stats` (summary counts by type).

3. **Higgins context injection** (`server/routes/chat.js`) — Both regular (`POST /api/chat`) and streaming (`POST /api/chat/stream`) Higgins endpoints now search Open Brain for thoughts relevant to the user's message and append them to the system prompt under `RELEVANT CONTEXT FROM OPEN BRAIN`. Non-blocking — a failed Open Brain fetch only warns, never breaks chat.

4. **Open Brain UI** (`public/open-brain.html`) — Three-tab page:
   - **Capture** — textarea with char counter, Ctrl+Enter shortcut, recent captures list
   - **Browse** — semantic search input with type/days filters, thought cards with type badges and similarity scores, plain-text response parser
   - **Templates** — 5 expandable capture patterns (Decision Record, Person Note, Key Insight, Meeting Debrief, AI-Readable Save) with examples, rationale, and "Use this template" pre-fill
   - Floating chat FAB → modal overlay with Search/Capture mode toggle for quick access without tab switching
   - Live stats bar showing thought counts by type

5. **Platform admin restriction** (`db/phase62-open-brain-module.sql`) — `platform_admin_only BOOLEAN` column added to `platform_modules`. `can_access_module()` rewritten to check this flag after the platform admin bypass, denying all non-platform-admins from restricted modules. `open_brain` module inserted with `nav_group = 'admin'`, `display_order = 63`, `platform_admin_only = TRUE`.

6. **Platform admin seeding** (`db/phase62-open-brain-module.sql`) — `jb@synergiai.io` inserted into `platform_admins` as `super_admin` via email lookup with `ON CONFLICT DO UPDATE`, ensuring idempotent access.
