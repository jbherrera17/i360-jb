This consolidated blueprint captures the complete development history from Phase 16 through Phase 56, providing a single reference document for all implemented features.

## Phase 55: Agency Tier Split + Soft Limit Infrastructure

Split the single `agency` tier into three graduated tiers with tier-group infrastructure for UI grouping and upgrade paths.

### New Agency Tiers

| Tier ID | Name | Price/mo | Members | Clients | Agents | Workflows | Key Features |
|---------|------|----------|---------|---------|--------|-----------|--------------|
| `agency_starter` | Agency Starter | $499 | 5 | 5 | 25 | 15 | Client portal, analytics |
| `agency_professional` | Agency Professional | $1,499 | 15 | 25 | 100 | 50 | + White-label, API, SSO |
| `agency_enterprise` | Agency Enterprise | $4,999 | 999 | 999 | 500 | 200 | Full enterprise scale |

### Database Changes

```sql
-- New column for UI grouping
ALTER TABLE subscription_tiers ADD COLUMN tier_group TEXT DEFAULT 'standard';
-- Values: 'standard', 'agency', 'platform', 'legacy'

-- Old 'agency' tier deactivated -> 'legacy' group
-- Existing orgs migrated to 'agency_starter'
-- Module min_tier references updated
-- Organizations constraint updated for new tier IDs
```

### Upgrade Path Infrastructure

- `tier_group` column enables grouped pricing cards (Standard vs Agency track)
- `allow_self_upgrade` flag per tier controls whether users can self-service upgrade
- `display_order` enables automatic next-tier detection for upgrade prompts

### Roadmap (Not Built)

- **Overage Billing**: `allow_overage`, `overage_rates` JSONB, Stripe metered billing
- **API Metering**: `api_usage_log` table, per-org middleware, monthly aggregation

**Files Created:**
- `db/phase55-agency-tier-split.sql` — Migration with upsert, constraint update, org migration

## Phase 56: Branding Expansion, Usage Nudges & Pricing Redesign

Three interconnected features: org-level branding with tier-gated sections, resource usage warnings/blocks, and a redesigned public pricing page.

### Branding Panel (admin-org-settings.html)

Full branding configuration panel with tier-locked sections:

| Section | Tier Required | Fields |
|---------|--------------|--------|
| **Logo & Identity** | All tiers | Logo URL, dark logo URL, favicon URL |
| **Color Theme** | All tiers | Primary, secondary, accent, sidebar color |
| **Typography** | Business+ | Heading font, body font (10 allowed fonts) |
| **App Naming** | Enterprise+ | App name, tagline (replaces "Insight 360") |
| **AI Assistant** | Enterprise+ | Assistant name, avatar (replaces "Higgins") |
| **White-Label** | Agency Pro+ | Custom login, email templates, portal message |

**Tier Lock UX:**
- Locked sections show blurred fields with overlay badge
- Badge text: "Requires [Tier Name]" with lock icon
- Fields within locked sections are non-interactive (`pointer-events: none`)

### Server-Side Validation (orgCustomization.js)

| Validation | Rule |
|------------|------|
| Color fields | Must match `/^#[0-9a-fA-F]{6}$/` |
| URL fields | Must pass `new URL()` constructor |
| Font fields | Must be in allowed list of 10 fonts |
| Tier enforcement | Strips white-label fields if org tier doesn't include feature |

### BrandingService (branding-service.js)

Runtime white-label injection loaded automatically by `navigation.js`:

```
BrandingService.load()
├── _getFromCache() → 5-min localStorage cache
├── _fetchBranding() → GET /api/org-customization/:orgId/branding
├── _applyColors() → CSS custom properties (--primary, --secondary, etc.)
├── _applyFonts() → Google Fonts dynamic loading + CSS vars
├── _updateSidebar() → Logo swap (dark/light theme aware)
├── _updateFavicon() → Dynamic favicon replacement
└── _updatePageTitle() → Replace "Insight 360" with custom app name
```

**Public API:**
- `BrandingService.load()` — Fetch and apply (called by navigation.js)
- `BrandingService.getAssistantName()` — Custom AI name or "Higgins"
- `BrandingService.getAppName()` — Custom app name or "Insight 360"
- `BrandingService.clearCache()` — Invalidate after saving new branding

### Usage Nudge System (usage-nudge.js)

Resource limit warnings and blocking modals across resource-creation pages.

**Architecture:**
```
UsageNudge.init()
├── GET /api/modules/usage → tier limits, current counts, warnings, blocks
├── renderBanner() → yellow warning bar after page header
│   └── "Approaching plan limits: 23/25 agents (92%)"
└── UsageNudge.checkBeforeCreate('agents')
    └── If blocked → ModalService alert + upgrade redirect
```

**Integration Points:**
- `agents.html` — Agent creation check
- `workflow-builder.html` — Workflow creation check
- `skills.html` — Skill creation check
- `context.html` — Context asset creation check
- `research-studio.html` — Research studio creation check
- `chat.js` — Conversation limit check

### Usage API (modules.js)

```
GET /api/modules/usage
Response: {
    tier: { id, name, display_order, tier_group, allow_self_upgrade },
    next_tier: { id, name, price_monthly },
    resources: [
        { resource: "agents", current: 23, max: 25, percent: 92 }
    ],
    warnings: [ /* resources at ≥80% */ ],
    blocks: [ /* resources at 100% */ ]
}
```
