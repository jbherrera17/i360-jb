### RLS Policy Fix for Service Role Access

#### Problem

Row-Level Security policies were blocking server-side operations even when using `SUPABASE_SERVICE_KEY`. The error:

```
Error: new row violates row-level security policy for table "context_assets"
```

#### Solution

Created comprehensive RLS policy update to allow service role bypass:

**File:** `db/phase19-fix-rls-service-role.sql`

```sql
-- Allow service role full access to assets
CREATE POLICY "Allow service role full access to assets" ON context_assets
    FOR ALL USING (
        auth.role() = 'service_role'
    );

-- Users can view their own assets, public assets, or ownerless assets
CREATE POLICY "Users can view own or public assets" ON context_assets
    FOR SELECT USING (
        auth.uid() = user_id
        OR visibility = 'public'
        OR user_id IS NULL
    );

-- Users can insert with their ID or null (for server operations)
CREATE POLICY "Users can insert own assets" ON context_assets
    FOR INSERT WITH CHECK (
        auth.uid() = user_id
        OR user_id IS NULL
    );
```

#### Tables Updated

- `context_assets` - Full service role access + user policies
- `agent_context_mappings` - Full service role access + ownership policies
- `context_asset_versions` - Full service role access + ownership policies

### New Endpoints

#### GET /api/agents/:id/context/mappings

Get context mappings for an agent with full asset details.

**Response:**
```json
{
  "success": true,
  "data": [
    {
      "id": "uuid",

        "id": "uuid",
        "name": "Asset Name",
        "asset_type": "company_description",
        "content_json": {},
        "content_text": "..."
      }
    }
  ]
}
```

#### POST /api/agents/:id/context/mappings

Add a context asset mapping to an agent.

**Request:**
```json
{
  "asset_id": "uuid",
  "injection_mode": "on_demand",
  "priority": 50
}
```
