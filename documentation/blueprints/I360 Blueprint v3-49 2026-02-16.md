## Executive Summary

Insight 360 is a **Values-Based AI Ecosystem** — a personal AI command center that aligns automated systems with organizational ethics. Version 3.49 delivers three sets of improvements: **Phase 57b** completes the legacy agency tier cleanup by deleting the deactivated `agency` row and removing all hardcoded references across the codebase; **Phase 58** replaces password-based user creation with Supabase email invitations, enabling a secure self-service onboarding flow; and **Research Studio Modernization** migrates inline modals to ModalService, adds SSRF protection, and fixes flashcard navigation bugs.

**Core Philosophy:** *"Technology should augment human brilliance—not replace it."*

## Phase 57b: Legacy Agency Tier Cleanup (v3.49)

| **Update fallback defaults** | `server/routes/platformAdmin.js` | Replace single `{ id: 'agency' }` with three sub-tier entries |
| **Update validTiers** | `server/routes/platformAdmin.js` | Remove `'agency'` from validation array |
| **Update TIER_ORDER** | `server/routes/pricing.js` | Replace `'agency'` with `'agency_starter', 'agency_professional', 'agency_enterprise'` |

| **Admin dropdowns** | `public/admin-platform.html` | Replace single agency option with three sub-tier options |

## Phase 58: Email Invitation System (v3.49)

### What Was Completed

Replaced password-based user creation with Supabase's `inviteUserByEmail()` API. Platform admins no longer set passwords when creating users — instead, an email invitation is sent and the user sets their own password via an accept-invite flow on the login page. Organization member invites also auto-create and invite non-existing users.

### Enhancements

| Enhancement | File(s) | Description |
|-------------|---------|-------------|
| **Invite-based user creation** | `server/routes/auth.js` | `POST /api/auth/users` uses `inviteUserByEmail()` instead of `createUser()` with password |
| **Accept invite endpoint** | `server/routes/auth.js` | `POST /api/auth/accept-invite` sets password, activates account, returns session |
| **Accept invite UI** | `public/login.html` | New form panel for setting password when accepting invitation |
| **Token type detection** | `public/login.html` | Detects `type=invite` or `type=magiclink` in URL hash to route to accept-invite flow |
| **Invite status** | `public/admin-platform.html` | New `invited` status badge, filter option, and "Resend" action button |
| **Resend invite** | `public/admin-platform.html` | `resendInvite()` calls `POST /api/platform/users/:id/resend-invite` |
| **Auto-invite on org add** | `server/routes/org-members.js` | Adding a non-existing email to an org auto-creates user and sends invite |
| **Rate limit handling** | `server/routes/auth.js`, `server/routes/org-members.js` | 429 status returned when Supabase email rate limit hit |
| **APP_URL config** | `.env.example` | New `APP_URL` variable for invitation redirect URLs |

### Files Modified

| File | Changes |
|------|---------|
| `server/routes/auth.js` | `accept-invite` endpoint, invite-based `POST /users`, rate limit handling |
| `server/routes/org-members.js` | Auto-invite non-existing users when adding to org |
| `public/login.html` | Accept invitation form, token type detection, activate account flow |
| `public/admin-platform.html` | "Invite User" button, invited status, resend invite, remove password field |
| `.env.example` | `APP_URL` variable |
| `db/phase58-invite-system.sql` | Migration for invite-related columns |

## Research Studio Modernization (v3.49)

### What Was Completed

Migrated Research Studio from inline HTML modals to ModalService, replaced all `alert()` calls with `showToast()`, fixed the page template to match platform standards, fixed flashcard navigation bugs, and added SSRF protection to URL source processing.

### Enhancements

| Enhancement | File(s) | Description |
|-------------|---------|-------------|
| **ModalService migration** | `public/js/research-studio.js`, `public/research-studio.html` | Create studio, add source, and output preview modals now use ModalService |
| **Inline modal removal** | `public/research-studio.html` | Removed ~90 lines of inline modal HTML |
| **Page template fix** | `public/research-studio.html` | Added `app-container`, `aside` sidebar, standard header with subtitle |
| **Toast notifications** | `public/js/research-studio.js` | All `alert()` calls replaced with `showToast()` |
| **Flashcard bug fix** | `public/js/research-studio.js` | `nextFlashcard()` and `updateFlashcardDisplay()` now use `currentFlashcardOutput` instead of `currentQuiz` |
| **Flashcard shuffle** | `public/js/research-studio.js` | Fisher-Yates shuffle for flashcard decks |
| **Source content editing** | `server/routes/researchStudio.js`, `server/services/researchStudioService.js` | `PATCH` sources with title and content, re-chunks on content change |
| **Model passthrough** | `server/routes/researchStudio.js` | `model` parameter passed through to output generation |
| **Output map** | `public/js/research-studio.js` | `outputsMap` avoids JSON serialization in onclick attributes |
| **SSRF protection** | `server/services/sourceProcessor.js` | `validateUrlSafety()` blocks localhost, private IPs, cloud metadata endpoints |
| **Supabase injection** | `server/services/sourceProcessor.js`, `server/services/studioOutputService.js` | `setSupabase()` for testability |

### Files Modified

| File | Changes |
|------|---------|
| `public/research-studio.html` | Page template, inline modals removed, DOMContentLoaded init |
| `public/js/research-studio.js` | ModalService, toasts, flashcard fixes, shuffle, outputsMap, source editing |
| `server/routes/researchStudio.js` | Source content update, model passthrough |
| `server/services/researchStudioService.js` | `updateSource()` function |
