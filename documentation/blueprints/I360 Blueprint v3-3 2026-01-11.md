## Executive Summary

Insight 360 v3.3 delivers a comprehensive overhaul of the Role Management system, rebranded as **Title Management**. This release introduces a new 3-column Edit modal with inline responsibility creation, full CRUD operations for Responsibilities, and enhanced onboarding that auto-assigns "All [Department]" system titles to new users. The terminology change clarifies the distinction between job titles (organizational) and system roles (access control).

**Key Achievements:**
- Renamed "Role Management" to "Title Management" throughout the system
- Implemented 3-column Edit modal (Basic Info, Responsibilities, Tags)
- Added full CRUD for Responsibilities with inline creation
- Enhanced onboarding wizard with title field and benefit-focused explanation
- Created database migration for system titles and department domain tags
- Updated all user documentation

## What's New in v3.3

### Terminology Change: Role → Title

| Old Term | New Term | Purpose |
|----------|----------|---------|
| Role Management | Title Management | Manages job titles within departments |
| Department Role | Title | Job function (e.g., "Marketing Manager") |
| Primary Role | Primary Title | User's main job function |

### System Titles

Each department now has an auto-generated "All [Department]" system title:

| Department | System Title | Access |
|------------|--------------|--------|
| Marketing | All Marketing | All marketing-tagged agents/workflows |
| Sales | All Sales | All sales-tagged agents/workflows |
| Finance | All Finance | All finance-tagged agents/workflows |
| HR | All HR | All HR-tagged agents/workflows |
| Operations | All Operations | All operations-tagged agents/workflows |
| Executive | All Executive | All executive-tagged agents/workflows |

**When Used:**
- New user doesn't specify a title during onboarding
- User's job doesn't match any predefined title
- User needs broad departmental access

### 3-Column Edit Modal

The new Title Management modal has three columns:

| Column | Contents |
|--------|----------|
| **1. Basic Information** | Department, Level, Title Name, Description |
| **2. Responsibilities** | Checkbox list with inline "Add" button, descriptions on same line |
| **3. Associated Tags** | Checkbox list grouped by category (skills, domains, functions) |

### Responsibilities CRUD

Full Create, Read, Update, Delete for Responsibilities:

| Operation | UI Location | Behavior |
|-----------|-------------|----------|
| **Create** | Responsibilities tab → "Add Responsibility" | Opens modal for new responsibility |
| **Create (Inline)** | Edit Title modal → Column 2 | Type name, click "+", auto-checks new item |
| **Read** | Responsibilities tab | Table view with usage count |
| **Update** | Responsibilities tab → pencil icon | Opens modal with existing data |
| **Delete** | Responsibilities tab → trash icon | Confirmation modal, prevents if in use |

### Onboarding Enhancement

The Profile step now includes:

1. **Department (Required)** - Must select before proceeding
2. **Title Field** - "What's your role at [Company]?"
3. **Help Text** - Benefit-focused explanation:
   - "Your title helps us recommend the right AI agents and workflows for your work."
   - "Leave blank to access all resources for your department."

**Auto-Assignment Logic:**
1. If user enters title matching existing title → assign that title
2. If no match or blank → assign "All [Department]" system title
3. Fallback → assign first available title for department

## Database Changes

### Schema Migration (phase22-title-management.sql)

```sql
-- Add domain_tag reference to departments
ALTER TABLE departments ADD COLUMN IF NOT EXISTS domain_tag TEXT;

-- Add is_system_title flag to department_roles
ALTER TABLE department_roles ADD COLUMN IF NOT EXISTS is_system_title BOOLEAN DEFAULT false;

-- Create index for efficient filtering
CREATE INDEX IF NOT EXISTS idx_department_roles_system_title
ON department_roles(is_system_title) WHERE is_system_title = true;

-- Create system titles for each department
INSERT INTO department_roles (id, department_id, name, description, role_level, is_system_title, ...)
SELECT gen_random_uuid(), d.id, 'All ' || d.name, 'Default title granting access...', 'ic', true, ...
FROM departments d WHERE d.is_active = true;

-- Auto-tag system titles with department domain tags
INSERT INTO role_tags (role_id, tag_id)
SELECT dr.id, t.id
FROM department_roles dr
JOIN departments d ON dr.department_id = d.id
JOIN tags t ON t.name = d.domain_tag
WHERE dr.is_system_title = true;
```

## API Changes

### New Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/roles/responsibilities/:id` | Get single responsibility by ID |
| PUT | `/api/roles/responsibilities/:id` | Update existing responsibility |
| DELETE | `/api/roles/responsibilities/:id` | Delete responsibility (soft by default) |

### Responsibility API Details

**GET /api/roles/responsibilities/:id**
```json
{
  "success": true,
  "data": {
    "id": "uuid",
    "name": "Budget planning",
    "description": "Manage departmental budgets",
    "parent_id": null,
    "role_count": 5
  }
}
```

**PUT /api/roles/responsibilities/:id**
```json
// Request
{
  "name": "Budget planning and forecasting",
  "description": "Updated description",
  "parent_id": "optional-parent-uuid"
}
```

**DELETE /api/roles/responsibilities/:id?hard=true**
- Soft delete (default): Sets `is_active = false`
- Hard delete: Removes record entirely (only if not assigned to any titles)

## Onboarding Flow

### Profile Step Changes

**Before:**
1. Avatar selection
2. Display Name
3. Department (optional)

**After:**
1. Avatar selection
2. Display Name
3. Department (required, marked with *)
4. Title field with explanation:
   - "What's your role at [Company]?"
   - Help text explaining benefits
   - Placeholder: "e.g., Marketing Manager, Sales Rep, Analyst"

### Title Assignment Logic

```javascript
async function assignUserTitle(userId, departmentId, titleInput, token) {
    // 1. Fetch available titles for department
    const departmentRoles = await fetchRoles(departmentId);

    // 2. Try to match user input to existing title
    if (titleInput) {
        roleToAssign = departmentRoles.find(r =>
            r.name.toLowerCase().includes(titleInput.toLowerCase())
        );
    }

    // 3. Fallback to system "All [Department]" title
    if (!roleToAssign) {
        roleToAssign = departmentRoles.find(r => r.is_system_title === true);
    }

    // 4. Assign as primary title
    await assignRole(userId, roleToAssign.id, { is_primary: true });
}
```
